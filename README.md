# LearnLoop AI

เว็บแอปภาษาไทยสำหรับเรียนจากเอกสารของตัวเอง Nuxt 3 / Vue / Tailwind แสดงหน้าภาพรวม ห้องเรียน ฝึกจำ และแผนผังความรู้ NestJS ให้บริการ API และควบคุมสิทธิ์ ส่วน PostgreSQL เก็บบทเรียน ประวัติและนัดทบทวน Redis / BullMQ ส่งงานไปยัง AI worker แยกจากเว็บ

## เปิดบน Windows

1. เปิด Docker Desktop ในโหมด Linux containers ให้ Engine พร้อมทำงาน แตก ZIP ทั้งโฟลเดอร์
2. เปิด Ollama บน Windows และตรวจว่า `ollama list` มี `qwen3.5:4b-q4_K_M` รุ่นนี้เรียกโมเดลผ่าน Ollama โดยตรง ตัวเปิดจะสร้าง .env เมื่อเปิดครั้งแรก ค่าเริ่มต้นสำหรับ Docker คือ `OLLAMA_URL=http://host.docker.internal:11434` และ `OLLAMA_MODEL=qwen3.5:4b-q4_K_M` หากเปลี่ยนโมเดลให้ใช้ชื่อตาม ollama list
3. ดับเบิลคลิก **Start LearnLoop AI.cmd** ครั้งแรก Docker จะดาวน์โหลดแพ็กเกจ สร้างฐานข้อมูล และเปิดเว็บที่ **http://localhost:4318** หรือรัน `docker compose up -d --build --wait` แล้วเปิด URL เอง
4. **โหมดทดลองในเครื่อง (ค่าเริ่มต้น):** เปิดเว็บผ่าน `http://localhost:4318` หรือ `http://127.0.0.1:4318` จะเข้าสู่ผู้เรียนทดลองโดยอัตโนมัติ ไม่ต้องสมัครหรือ Login แล้วสร้างเป้าหมายและหัวข้อแรกได้ทันที ข้อมูลทดลองถูกเก็บแยกจากบัญชีจริงใน PostgreSQL
5. หากต้องการกลับมาใช้ระบบ Login ให้ตั้ง `DEV_AUTH_BYPASS=false` ใน `.env` แล้วรัน `docker compose up -d --force-recreate api worker` ระบบสมัครบัญชี/เข้าสู่ระบบด้วยรหัสผ่านและ OIDC ยังอยู่เหมือนเดิม หากต้องการใช้บัญชีองค์กร ตั้งค่า OIDC_ISSUER, OIDC_CLIENT_ID, OIDC_CLIENT_SECRET และลงทะเบียน callback `http://localhost:4318/v1/oidc/callback` กับผู้ให้บริการ
   **ความปลอดภัย:** โหมดทดลองเปิดได้เฉพาะเมื่อ `PUBLIC_URL` เป็น HTTP loopback (`localhost` หรือ `127.0.0.1`) และพอร์ตเว็บใน `compose.yaml` ผูกกับ `127.0.0.1` เท่านั้น ห้ามเปิดโหมดนี้บนเซิร์ฟเวอร์สาธารณะ
6. หลังแก้ .env รัน `docker compose up -d --force-recreate api worker` เพื่อให้ API และ worker อ่านค่าใหม่ ดูสถานะด้วย `docker compose ps` และดูข้อความขัดข้องด้วย `docker compose logs --tail=60 api worker web`
7. หยุดด้วย `docker compose down` ข้อมูลจะอยู่ใน volumes สำหรับ PostgreSQL และ Redis เปิดอีกครั้งด้วยตัวเปิดเดิม

เมื่อรัน API และ worker โดยตรงบน Windows ใช้ OLLAMA_URL=http://127.0.0.1:11434 ทั้งสองบริการ หากรันใน Docker แล้วปุ่ม AI ยังไม่พร้อม ให้ตรวจว่า container เข้าถึง http://host.docker.internal:11434/api/tags ได้ แล้วรีเฟรชหน้าเว็บ แหล่งเรียน คำตอบ และแผนถูกประมวลผลโดย Ollama ในเครื่อง

## ทดลองหนึ่งรอบ

- ในห้องเรียน นำเข้า PDF ที่มีข้อความ (สูงสุด 8 MB), TXT, Markdown หรือวาง transcript โดยตรง รองรับข้อความที่สกัดได้สูงสุด 150,000 ตัวอักษร เอกสารที่เป็นภาพต้องทำ OCR ก่อนนำเข้า ระบบเก็บข้อความเป็นส่วนละไม่เกิน 1,800 Unicode code points ใน PostgreSQL
- หลังนำเข้า TXT, Markdown, transcript หรือ PDF เปิดหน้า **ห้องเรียน → แหล่งเรียน** แล้วเลือกส่วนเนื้อหา จะมีแท็บ **ต้นฉบับ**, **อ่านง่ายด้วย AI**, **สรุปสาระสำคัญ**, และ **Mind Map** แท็บต้นฉบับมีตัวเลือกเปิดอ่านทั้งบทเรียนพร้อมแบ่งย่อหน้าและแสดงหัวข้อให้อ่านง่าย ส่วนผล AI สร้างจาก **ส่วนเนื้อหาที่เลือกเท่านั้น** เพื่อควบคุมบริบทและความยาว ผลอ่านง่ายมีบทสรุป หัวข้อย่อย ประเด็นจำ และคำศัพท์; ส่วน Mind Map แสดงประเด็นหลักและกิ่งความสัมพันธ์แบบ responsive
- กด **สร้างด้วย AI** ภายในแท็บที่ต้องการครั้งแรก ผลจะถูกเก็บใน PostgreSQL เป็น `SourceArtifact` ต่อบทเรียน/ส่วน/ชนิด (reading_aid หรือ mindmap) เมื่อกลับมาเปิดแท็บเดิมจะดึง cache ให้โดยไม่เรียก Ollama ซ้ำ และเปิดผลเดิมได้แม้ Ollama ไม่พร้อม เนื้อหาที่ AI เรียบเรียงควรตรวจสอบเทียบต้นฉบับเสมอ หากเปลี่ยนเป็นส่วนอื่นจะมี artifact แยกต่างหาก
- เปิดบทเรียน เลือกส่วนเนื้อหา แล้วกด **สร้าง 3 คำถามด้วย AI** จะได้โจทย์ฝึกความจำ ประยุกต์ และอธิบาย ระบบตรวจว่าข้อความอ้างอิงอยู่ในส่วนที่เลือกก่อนบันทึกชุดคำถาม
- หน้า **ห้องเรียน** มี **คลังคำถาม (Question Bank)** รวมทุกคำถามของเป้าหมาย ค้นหาและกรองตามหัวข้อ ประเภท และที่มา (AI/สร้างเอง) ได้ เลือก **ดูแนวคำตอบ** เพื่ออ่านคำใบ้และข้อความอ้างอิง หรือกด **ฝึกข้อนี้** เพื่อเปิด Active Recall ของข้อที่เลือกโดยตรง แนวคำตอบถูกโหลดจาก API เฉพาะตอนกดดู และตรวจสิทธิ์เจ้าของคำถามเสมอ
- ไปหน้า **ฝึกจำ** ตอบเองก่อนเปิดแนวคำตอบ กด **ให้ AI ประเมินคำอธิบาย** เพื่อดูข้อที่ตรงกับหลักฐาน ข้อที่ขัดกับหลักฐาน และข้อที่ยังพิสูจน์ไม่ได้ พร้อมคะแนนตามเกณฑ์ 0, 25, 50, 75 หรือ 100% และแนวทางฝึกต่อ AI ใช้คำถาม คำตอบของผู้เรียน แนวคำตอบ ข้อความอ้างอิง และเกณฑ์ของข้อนั้น การตรวจตำแหน่งข้อความอ้างอิงช่วยให้ตรวจย้อนกลับได้ ผู้เรียนยังควรอ่านเหตุผลเทียบกับต้นฉบับ
- ให้คะแนน Again / Hard / Good / Easy เพื่อบันทึกนัดครั้งถัดไป Again นัดใน 10 นาที Hard นัดใน 1 วัน Good/Easy เริ่มที่ 3/7 วันและปรับตามช่วงเดิมกับความมั่นใจ ผล AI ต่ำกว่า 50% ที่มีอยู่ตอนให้คะแนนจะลดระดับสูงสุดเหลือ Hard
- **วางแผนรอบเรียนโฉมใหม่:** เลือกเวลา 20, 30, 45 หรือ 60 นาที → ระบบแสดงแผนล่วงหน้าเป็นการ์ด 5 ช่วงที่มีเป้าหมาย กิจกรรมที่ต้องทำ และนาทีที่แบ่งตามเวลาจริง โดย **ไม่ต้องใช้ AI**; หาก Ollama พร้อมสามารถกด **ให้ AI ปรับคำแนะนำ** เพื่อเสริมคำแนะนำในแต่ละช่วงโดยไม่แทนที่โครงสร้างที่อิงหลักการเรียนรู้
- ขั้นที่ 1 **Mental Priming:** ปิดโน้ตเรียกความรู้เดิม; ขั้นที่ 2 **Elaboration + Dual Coding:** ถามว่า “ทำไม” และวาดความสัมพันธ์; ขั้นที่ 3 **Active Retrieval:** ตอบคำถามที่ระบบเลือกจากคลังตามกำหนดโดยไม่ดูเฉลย; ขั้นที่ 4 **Interleaving + Desirable Difficulties:** ฝึกสลับไปยังโจทย์อีกหัวข้อหากมีและเลือกระดับความยากพอดี; ขั้นที่ 5 **Feynman + Feedback + Rest:** อธิบายให้มือใหม่ฟัง ตรวจจุดที่ไม่เข้าใจ และพักสายตา
- ระหว่างรอบเรียนหน้าเว็บจะแสดง progress bar, ตัวจับเวลาต่อช่วง, โจทย์ที่เลือกและปุ่มเปิด Active Recall, พื้นที่เขียนหลักฐานการเรียนรู้ บันทึกทีละช่วงลง PostgreSQL (`StudySession.evidence`) และกลับมาเรียนต่อได้หลังรีเฟรชหรือไปหน้าอื่น ไม่บังคับให้ตอบภายในเวลาที่กำหนด
- **Spaced Repetition:** กล่องด้านล่างแสดงจำนวนคำถามที่ถึงกำหนดและนัดถัดไปจากข้อมูลจริงในฐานข้อมูล กดเข้าทบทวนได้ทันที; เมื่อฝึกแล้วให้ประเมิน Again / Hard / Good / Easy เพื่อกำหนดวันทบทวน ไม่ใช่เชื่อว่าทำครบหนึ่งรอบแล้วจำได้อัตโนมัติ
- ปุ่มกางดู **8 เทคนิคการเรียนรู้** อธิบายเหตุผลของแต่ละกิจกรรม รวมทั้งการพัก การนอน และการปรับความยากให้เหมาะสม เหมาะกับทั้ง Programming และภาษาอังกฤษ
- เชื่อมหัวข้อในแผนผัง หากหัวข้อควรฝึกเพิ่ม ภาพรวมจะแสดงปุ่มกลับไปอ่านพื้นฐานที่เชื่อมไว้ กิจกรรมประยุกต์ในรอบเรียนเลือกโจทย์จากอีกหัวข้อในเป้าหมายเมื่อมี

## จัดการเป้าหมายและหัวข้อ (CRUD)

- ในเมนูด้านซ้ายเลือก **จัดการข้อมูล** หรือกด **จัดการเป้าหมายและหัวข้อ** ด้านบนเพื่อเปิดหน้า Data Table
- แท็บ **เป้าหมาย** สามารถสร้างเป้าหมายใหม่ เลือกประเภท Programming / English / General ค้นหา เรียงชื่อ แก้ไขชื่อและประเภท หรือเปิดเป้าหมายที่ต้องการ
- แท็บ **หัวข้อ** สามารถสร้างหัวข้อในเป้าหมายที่เลือก ค้นหาและกรองตามเป้าหมาย แก้ไขชื่อ เปิดห้องเรียนของหัวข้อนั้น และลบหัวข้อ
- แท็บ **ประเภท** เพิ่มประเภทเป้าหมายได้เอง เช่น Backend, AI, Japanese หรือวิชาอื่น ๆ จากนั้นตัวเลือกใหม่จะปรากฏในช่องประเภทเมื่อสร้างและแก้ไขเป้าหมาย
- ประเภทพื้นฐาน **General, Programming, English** ยังอยู่เสมอและลบไม่ได้ ประเภทที่สร้างเองสามารถแก้ชื่อได้ โดยเป้าหมายที่ใช้ชื่อเดิมจะเปลี่ยนตามใน transaction เดียวกัน
- ลบประเภทที่สร้างเองได้เฉพาะเมื่อไม่มีเป้าหมายกำลังใช้งาน ต้องพิมพ์ชื่อเพื่อยืนยัน และไม่ลบบทเรียนหรือเป้าหมาย
- ประเภทที่สร้างเองเก็บใน PostgreSQL แยกตามบัญชีผู้เรียน ไม่มีผลต่อข้อมูลบัญชีอื่น การอัปเดตนี้มี Prisma migration เพิ่มตาราง `GoalCategory` โดยไม่แก้ข้อมูลประเภทของเป้าหมายที่มีอยู่
- ก่อนลบต้องกด **ลบ** จากแถวที่ต้องการ ตรวจจำนวนข้อมูลที่เกี่ยวข้องและพิมพ์ชื่อรายการให้ตรงทุกตัวอักษร แล้วกด **ลบข้อมูลถาวร** ซึ่งไม่สามารถกู้คืนจากหน้าเว็บได้
- **การลบหัวข้อ** จะลบบทเรียน (รวม AI reading aid/Mind Map), คำถาม, ประวัติการตอบ, รอบเรียน และความสัมพันธ์ที่อ้างถึงหัวข้อนั้น ส่วนเป้าหมายอื่นไม่กระทบ
- **การลบเป้าหมาย** จะลบทุกหัวข้อและข้อมูลทั้งหมดภายใต้เป้าหมายนั้นด้วย จึงควรสำรอง PostgreSQL ก่อนลบข้อมูลจริง
- Backend ตรวจสิทธิ์เจ้าของทั้งการแก้ไขและลบ ใช้ transaction สำหรับลบข้อมูลที่มี foreign keys แบบ RESTRICT และตรวจ Origin ของ PATCH/DELETE เช่นเดียวกับ POST
- เช่น หากต้องการลบรายการทดลอง `เทส` (เป้าหมาย) และ `ฟด` (หัวข้อ) ที่สร้างใน Docker ให้เปิด **จัดการข้อมูล** แล้วลบรายการนั้นผ่านตารางโดยตรง ระบบไม่ลบข้อมูลใดล่วงหน้าเพียงเพราะนำโค้ดเวอร์ชันใหม่มารัน

## นำเข้ารุ่น SQLite เดิม

ใช้กับฐานข้อมูลจากรุ่น LearnLoop-Windows ในแชตนี้ ปิดโปรแกรมรุ่นเก่าและสำรองไฟล์ก่อน เริ่มบริการรุ่นใหม่ แล้วรันจากโฟลเดอร์ที่มี compose.yaml โดยเปลี่ยนพาธเป็นไฟล์จริง

```powershell
docker compose cp "C:\path\to\learnloop.sqlite" api:/tmp/learnloop.sqlite
docker compose exec api node dist/import-legacy.js /tmp/learnloop.sqlite
```

นำเข้าบัญชี เป้าหมาย หัวข้อ บันทึก แหล่งเรียน คำถาม ประวัติ นัดทบทวน ความสัมพันธ์และรอบเรียนเป็นธุรกรรมเดียว ใช้อีเมลและรหัสผ่านเดิมเข้าระบบใหม่ได้ หากมีบัญชีอีเมลซ้ำที่สร้างในระบบใหม่ การนำเข้าจะหยุดเพื่อให้ตรวจสอบ ใช้ไฟล์ต้นทางชุดเดียวต่อฐานข้อมูลปลายทาง ร่างในเบราว์เซอร์และคุกกี้เข้าระบบเป็นข้อมูลเฉพาะรุ่น

## โครงสร้างและการตรวจสอบ

- apps/web เป็น Nuxt มีคอมโพเนนต์ตามสี่หน้าจอ และ proxy สำหรับส่ง /v1 ไปยัง API
- apps/api/src/auth.ts รองรับรหัสผ่านแบบ scrypt, คุกกี้ HttpOnly และ OIDC Authorization Code + PKCE
- apps/api/src/learning.ts และ engine.ts ดูแลสิทธิ์ การจัดรอบเรียน แผนผังและการนัดทบทวน
- apps/api/src/jobs.ts รับงานและตรวจเจ้าของงานก่อนส่งสถานะ ส่วน worker.ts และ ai/provider.ts ติดต่อ LLM ตรวจรูปแบบผลลัพธ์ และบันทึกข้อมูลหลังผ่านการตรวจ
- apps/api/prisma มี schema และ SQL migration สำหรับ PostgreSQL รวม SourceArtifact (JSONB) พร้อม unique key ต่อ `sourceId, section, kind`; migration ใหม่จะทำงานอัตโนมัติผ่าน `prisma migrate deploy` เมื่อรัน Docker
- เรียก `docker compose exec api npm test` หลังเปิดระบบเพื่อทดสอบกฎการเรียนและการเชื่อมต่อ Ollama
- API ใช้ JSON ยกเว้น sources/pdf ที่ใช้ multipart/form-data ฟิลด์ file, topicId, title
- GET /v1/health, /v1/state และ /v1/ai/jobs/:id อ่านสถานะ ส่วน POST /v1/ai/generate, /v1/ai/tutor, /v1/ai/planner รับ resourceId ของแหล่งเรียน การตอบ หรือหัวข้อตามลำดับ แล้วคืน jobId สำหรับติดตามผล
- ในโหมดพัฒนาให้ใช้ Node 22.13+ รัน npm ci และ npm run build ในแต่ละแอป API ต้องมี DATABASE_URL และใช้ npx prisma migrate deploy ก่อน npm start เริ่ม worker ด้วย npm run worker และตั้ง REDIS_HOST ทั้งสองบริการ Nuxt ใช้ API_ORIGIN ชี้ไปที่ API เช่น http://127.0.0.1:3001

รุ่นนี้เก็บข้อความที่สกัดได้จากเอกสาร การเก็บไฟล์ต้นฉบับใน Object Storage, OCR, การฝึกด้วยเสียง และการรันโค้ดผู้เรียนยังเป็นงานต่อยอด
